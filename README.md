# Memento — веб-приложение-напоминатор с ИИ-агентами

Тёмный «стеклянный» интерфейс по вашему референсу: главный экран с виджетами, галерея виджетов,
экран блокировки с уведомлениями и шторка редактирования напоминания с колесом времени.
Плюс то, чего на макете не было: **пайплайн из 5 ИИ-агентов на Claude Sonnet 5**, которые реально
меняют приложение, и **коннекторы** к внешним сервисам.

## Быстрый старт

```bash
cd memento
npm install
npm run dev        # http://localhost:5173
```

Прод-сборка: `npm run build` → `npm run preview`.
Зависимостей ровно три (React, ReactDOM, Vite) — остальное своё.

## Что внутри

### Экран приложения (как на макете)
- **Главная**: приветствие «Добрый вечер, Александр», кольцо прогресса 3/6, виджет «Сегодня»
  со временем, приоритетами (Высокий / Средний / Низкий), местом и круглыми чекбоксами,
  виджеты «Следующее» и «Прогресс дня».
- **Виджеты**: переключатель размера «Сегодня» — **2×2 / 4×2 / 4×4** (как на фото), предпросмотры
  и список всех виджетов с тумблерами: Следующее, Прогресс дня, Ближайшая неделя, Расписание
  на день (4×4, с таймлайном и кнопками «+10 мин» / «Изменить»), Агент.
- **Календарь**: месяц, дни с точками-событиями, фильтр Все / Активные / Выполненные.
- **Напоминания**: центр уведомлений с кнопками «Отложить 10 мин» и «Выполнено» — как в
  push-карточках на макете.
- **Экран блокировки**: часы с секундами, дата, стопка карточек «Memento · Через 23 мин» и
  «Нажми, чтобы открыть».
- **Шторка напоминания**: иконка, дата (+ быстрые чипы и системный календарь), **колесо времени**
  как в референсе, повтор, заметки, место, «Уведомление: за 10 минут», приоритет, «Сохранить».
- **Профиль**: имя, тема (Графит / Уголь), размер виджета, тумблеры уведомлений/звука/проверки,
  несколько профилей, сброс демо-данных.

### ИИ-агенты: Claude Sonnet 5, главный всех проверяет
Пайплайн вкладки **Агенты**:

| Агент | Роль |
|---|---|
| **Memento Orchestrator** (главный) | ставит задачу, распределяет работу, проверяет всё до конца |
| NLU · Парсер намерения | разбирает фразу: смысл, дата, время, повтор, приоритет |
| Планировщик | считает календарь, разрешает конфликты слотов, собирает вызовы инструментов |
| Редактор напоминаний | реально меняет данные приложения |
| Валидатор (QA) | перечитывает базу заново и подтверждает каждую операцию |

Как это работает по шагам: вы пишете «Напомни в пятницу в 19:30 ужин с семьёй» → парсер даёт
`{title: «Ужин с семьёй», дата: ближайшая пятница, время: 19:30, уверенность 82%}` →
планировщик проверяет занятость слота → редактор вызывает `create_reminder` → валидатор читает базу
повторно и подтверждает запись → главный агент отвечает «Сделано ✓» и всё видно в журнале.

Умеет: создавать, изменять, удалять, отмечать выполненным, откладывать, читать состояние,
переключать виджеты и настройки, открывать экраны. Автономные задачи: **Аудит расписания**,
**Разгрузить вечер**, **Демо-сценарий** (5 команд подряд).

### Коннекторы и MCP-шина
- Инструменты приложения описаны контрактом (`TOOLS`): имя, назначение, схема параметров —
  совместимо с MCP. На вкладке «Инструменты» у каждого есть кнопка **тест**: агент делает реальный вызов.
- **Anthropic Claude API**: если задать `ANTHROPIC_API_KEY`, локальный шлюз (`/api/claude`) будет
  обращаться к настоящей модели. Без ключа работает встроенный движок — приложение полностью автономно.
- **Google/Apple Календарь**: выгрузка `.ics` (с RRULE и VALARM).
- **Telegram-бот** и **Webhook / n8n**: тест-запрос через локальный шлюз `/api/outbound` (без CORS-проблем).
- **Notion/Markdown**: выгрузка базы в `.md`.
- **Системные уведомления браузера**: настоящий `Notification` при срабатывании напоминания.

### Срабатывания
Внутренний планировщик раз в секунду проверяет время: напоминание всплывает тостом, звуком
(короткий WebAudio-сигнал), попадает в центр уведомлений и на экран блокировки, а повторяющиеся
(ежедневно / по будням / еженедельно / ежемесячно) автоматически переносятся на следующий раз.


## Деплой на RelaxDev

Проект подготовлен под российский PaaS [relaxdev.ru](https://relaxdev.ru/docs) по официальной
инструкции платформы (её копия лежит в репозитории: `.claude/skills/relaxdev-deploy/SKILL.md`).

**Настройки в панели при создании проекта:**

| Параметр | Значение |
|---|---|
| Репозиторий | `DimaCharon/memento`, ветка `main` |
| Тип сборки | **Node.js** (автоопределение обычно ставит его; если выбралось «Vite/React — статика», переключите на Node.js в настройках) |
| Команда сборки | `npm run build` |
| Команда запуска | `npm start` |
| Порт | платформа задаёт `PORT=8080` сама — сервер читает его из окружения |
| База данных | не нужна |
| Автодеплой | включить — по push в `main` проект пересоберётся сам |

**Переменные окружения (вкладка «Переменные») — все необязательные:**

| Переменная | Зачем |
|---|---|
| `ANTHROPIC_API_KEY` | реальный Claude за пайплайном агентов. Без ключа работает встроенный локальный движок |
| `ANTHROPIC_MODEL` | модель, по умолчанию `claude-sonnet-4-5` |
| `OUTBOUND_PROXY_URL` | если Telegram или другой внешний API недоступен с серверов в РФ: адрес берётся в «Переменные» → «Webhook / Proxy» → «Получить адрес прокси» |
| `TG_OPTION=1` | если пользуетесь коннектором «Telegram-бот» (доступ к `api.telegram.org` по IPv6) |

### Как устроен запуск

- `npm run build` — `tsc -b && vite build`, фронтенд собирается в `dist/`.
- `npm start` — `node server.mjs`: один постоянный процесс на переднем плане, слушает
  `0.0.0.0` и `process.env['PORT']`. Отдаёт статику из `dist/` с SPA-фолбэком и обслуживает
  внутренний шлюз агентов:
  - `GET /api/health` — состояние (задан ли ключ Claude, поднят ли прокси),
  - `POST /api/claude` — прокси к Anthropic API (при отсутствии ключа отвечает `fallback: true`,
    и приложение молча работает на локальном движке),
  - `POST /api/outbound` — тест-запросы коннекторов (Telegram, webhooks) с защитой от SSRF.
- Переменные читаются через `process.env['ИМЯ']`, поэтому подстановка платформой
  `auto-generated-stub-for-build` не ломает значения по умолчанию; сама строка-заглушка
  распознаётся и игнорируется.
- Исходящие запросы идут через `undici.ProxyAgent`, если задан прокси: встроенный `fetch`
  в Node переменные `HTTP_PROXY`/`HTTPS_PROXY` не читает.
- `Dockerfile` в репозитории — запасной вариант, применяется только при типе сборки «Docker».

## Структура

```
src/
  agent/agents.ts     описание агентов, инструменты, настройки по умолчанию
  agent/engine.ts     NLU-парсер, исполнитель операций, пайплайн, автономные задачи
  components/         телефон, виджеты, шторки, экраны, агенты, коннекторы
  lib/date.ts         русские даты, «через 24 мин», повторения, звук
  store.tsx           состояние, localStorage, планировщик, срабатывания
vite.config.ts        локальный шлюз /api/claude и /api/outbound
```

Данные хранятся только в localStorage браузера. «Сбросить демо» в профиле возвращает исходный набор.
