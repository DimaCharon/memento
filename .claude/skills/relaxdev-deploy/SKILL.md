# RelaxDev: подготовка проекта к деплою

RelaxDev собирает Git-репозиторий в Docker-контейнер и запускает его на
серверах в России. Репозиторий подключается из GitHub, GitLab, GitVerse или
GitFlic, каждый push в выбранную ветку пересобирает проект. Контейнер работает
постоянно, без холодного старта, поэтому подходят боты, воркеры и WebSocket.

Сборку запускает человек: кнопкой в панели https://relaxdev.ru/dashboard или
push в ветку проекта. Задача агента — подготовить репозиторий и подсказать,
что настроить в панели.

Документация: https://relaxdev.ru/docs · полный контекст для ИИ: https://relaxdev.ru/llms-full.txt

## Перед первым деплоем

1. **Порт 8080.** Трафик приходит только на 8080. Платформа задаёт `PORT=8080`,
   а для рантаймов, которые `PORT` не читают, — `SERVER_PORT`, `UVICORN_PORT`,
   `FLASK_RUN_PORT`, `SANIC_PORT`, `QUARKUS_HTTP_PORT`. Слушайте `0.0.0.0` и порт
   из окружения: порт-константа или `127.0.0.1` дают 502 при рабочем контейнере.
2. **Стек** определяется автоматически по `package.json`, `requirements.txt` или
   `pyproject.toml`, `go.mod`, `pom.xml` или `build.gradle`, `composer.json`.
   Для типовых проектов Dockerfile не нужен. Закоммитьте lock-файл.
3. **Свой Dockerfile** используется, когда в настройках проекта выбран тип
   сборки Docker. При другом типе платформа генерирует Dockerfile сама, и файл
   из репозитория не применяется — частая причина «правки в Dockerfile не
   работают». Делайте multi-stage сборку и ставьте `ENV NODE_ENV=production`
   в финальной стадии: в одностадийной сборке в образе может остаться
   `NODE_ENV=development`.
4. **Монорепозиторий:** если приложение лежит в подпапке, выберите её
   в настройках проекта, иначе сборка ищет `package.json` в корне.
5. **Секреты** задаются в панели, вкладка «Переменные», и подставляются при
   запуске. Не кладите их в Dockerfile через `ARG` или `ENV` — останутся
   в слоях образа.

## Заглушки переменных

На этапе сборки платформа находит в исходниках обращения `process.env.ИМЯ`
и подставляет переменным, которых нет в проекте, строку
`auto-generated-stub-for-build` — так проект соберётся в любом случае.
Заглушка остаётся и в работающем приложении, не только при сборке. Поэтому:

- `process.env.ИМЯ || 'значение по умолчанию'` не сработает — строка не пустая;
- числовые переменные превращаются в `NaN`;
- «invalid URL», «invalid connection string», «Invalid API key» обычно
  означают заглушку, а не неверное значение.

Не подменяются только `NODE_ENV` и `PORT`. Список переменных с заглушкой
(с файлом и строкой) стоит в начале лога сборки и в баннере «Переменные
без значения» на странице проекта — сверяйтесь с ним.

Что делать:

- задать переменную в панели, вкладка «Переменные». Серверной переменной
  хватит обычного редеплоя, `NEXT_PUBLIC_*` вшиваются в код браузера и
  требуют полной пересборки;
- нужен фолбэк — читать через скобки: `process.env['ИМЯ'] || 'дефолт'`.
  Такую запись сканер не видит, заглушки не будет. Для `NEXT_PUBLIC_*` не
  подходит, и не поможет, если переменные проверяются при сборке (zod, t3-env).

## Telegram-боты и внешние API

- `api.telegram.org` с серверов доступен только по IPv6. У проектов типа
  «Telegram Bot» нужная сеть подключается сама; веб-проекту, который ходит
  в Telegram, добавьте переменную `TG_OPTION=1`.
- Бот по умолчанию работает на long polling, и его домен отвечает 404.
  Чтобы открыть HTTP-эндпоинты бота (вебхук, мини-приложение), задайте
  `WEB_PORT` — порт, который слушает приложение.
- `Conflict: terminated by other getUpdates request` — запущен второй
  экземпляр того же бота.
- Веб-проект может ходить в Telegram и через исходящий прокси (ниже).

## Вебхуки и прокси

Вебхук — когда внешний сервис приходит к приложению, прокси — когда
приложение ходит наружу. Оба настраиваются в панели: «Переменные» →
«Webhook / Proxy».

- **Приёмник вебхуков** — постоянный адрес `https://hook.relaxweb.ru/r/…` на
  зарубежном сервере. Принимает вебхуки Telegram, платёжных систем и других
  сервисов и пересылает в проект по указанному пути, заголовки без изменений.
  Для Telegram вебхук ставится кнопкой «Подключить к Telegram»; секрет из
  `TELEGRAM_WEBHOOK_SECRET` приходит в заголовке
  `X-Telegram-Bot-Api-Secret-Token`. Бот должен слушать путь из приёмника.
- **Исходящий прокси** — для API, которые не открываются с серверов в России
  (таймауты, обрыв загрузки). Адрес — кнопкой «Получить адрес прокси».
  Рекомендуемый способ — точечно: адрес в переменной под своим именем
  (например, `OUTBOUND_PROXY_URL`) и диспетчер только в нужном запросе:

  ```js
  import { fetch, ProxyAgent } from 'undici';
  const proxy = new ProxyAgent(process.env['OUTBOUND_PROXY_URL']);
  const res = await fetch(url, { dispatcher: proxy });
  ```

  `fetch` и `ProxyAgent` — из одного пакета `undici`. В Python — параметр
  `proxy` у `httpx.AsyncClient`.
- **`RELAXDEV_PROXY_URL`** включает прокси для всего проекта: платформа ставит
  `HTTP_PROXY`, `HTTPS_PROXY` и `NO_PROXY` (база, Redis и `*.relaxdev.ru`
  идут напрямую). Встроенный `fetch` в Node их не читает — в Next.js добавьте
  в `instrumentation.ts`:
  `setGlobalDispatcher(new EnvHttpProxyAgent())` из пакета `undici`.

## Переезд с Vercel

1. Переменные: `npx vercel link`, затем
   `npx vercel env pull .env.vercel --environment=production` и вставить файл
   целиком во вкладку «Переменные». Кавычки снимаются, `VERCEL_*` и `TURBO_*`
   пропускаются. Значения Sensitive Vercel не выгружает — вписать вручную.
2. База: создать базу во вкладке «База данных». Прежний `DATABASE_URL`
   сохранится как `OLD_DATABASE_URL` и сам подставится в «Импорт из другой
   базы данных». Строку с пулером Neon можно брать как есть, `DIRECT_URL`
   не нужен.
3. Код: настройки клиента базы под serverless (`max: 1`, `prepare: false`)
   на постоянном сервере не нужны — уберите их, запросы пойдут параллельно.

## Базы данных

У команды есть PostgreSQL и Redis, строки подключения — в панели. Для доступа
снаружи (миграции, DBeaver, CI) откройте внешний порт и добавьте свой IP
в белый список, иначе `P1001 Can't reach database server`. Из облачных IDE
и CI-раннеров добавляйте их внешний IP (`curl ifconfig.me`). Миграции во время
сборки требуют включить сборку с доступом к БД в настройках проекта; проще
перенести их в команду запуска.

Данные из другой PostgreSQL переносятся импортом по строке подключения
(см. «Переезд с Vercel»).

**Prisma.** При сборке выполняется `prisma generate`, а при сборке с доступом
к БД — `prisma db push` с учётом версии: для Prisma 7 без `--skip-generate`,
которого в ней нет. `db push` приводит базу к `schema.prisma`: если схема
отстаёт от реальной базы, держите её в актуальном состоянии. Без Prisma
в проекте сборка её не трогает и не скачивает.

## Домен и превью

Технический адрес — `<имя-проекта>.relaxdev.ru` с HTTPS. Свой домен: A-запись
на IP из панели проекта, сертификат Let's Encrypt выпускается и продлевается
сам. Ветки можно поднимать превью-окружениями на адресах `*.preview.relaxdev.ru`.

## Симптомы

| Симптом | Вероятная причина |
|---|---|
| Сборка прошла, адрес отдаёт 502 | Приложение слушает не `PORT` (8080) или `127.0.0.1` |
| Контейнер сразу останавливается | Главный процесс завершается: команда запуска должна работать на переднем плане |
| `COPY failed`, не найден `package.json` | Не выбрана папка проекта в монорепозитории или файл не закоммичен |
| `Cannot find module` только на сервере | Регистр букв в пути импорта (Linux различает) или файл в `.gitignore` |
| «invalid URL» при сборке или в работе | Заглушка `auto-generated-stub-for-build` вместо переменной — см. баннер «Переменные без значения» |
| `process.env.ИМЯ \|\| 'дефолт'` не срабатывает | Заглушка: задайте переменную или читайте через `process.env['ИМЯ']` |
| Таймауты к `api.telegram.org` | Нет IPv6-сети: тип проекта «Telegram Bot», `TG_OPTION=1` или прокси |
| `ETIMEDOUT` к внешнему API при заданном прокси | Запрос идёт мимо прокси: встроенному `fetch` нужен `dispatcher` |
| Вебхук Telegram не доходит | Подключите приёмник вебхуков и проверьте путь, который слушает бот |
| `P1001` | IP не в белом списке базы |
